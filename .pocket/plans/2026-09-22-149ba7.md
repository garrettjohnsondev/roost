## Task

Add a --json flag to tools/gen-avatars.mjs that prints the manifest to stdout as JSON instead of writing pool.json, document the flag in the ROADMAP Phase 1 section, and add a unit test for the manifest-building logic.

## Acceptance criteria

- `node tools/gen-avatars.mjs --json --limit 0` (with all planned avatars already present, or none due for generation) prints valid JSON to stdout and does not modify `web/public/avatars/pool.json` (verify via `git status`/mtime unchanged).
- `node --test tools/gen-avatars.test.mjs` exits 0 and its assertions actually exercise `buildManifest()`'s filtering (a subject with `isDone` false is excluded from `avatars`).
- Running `node tools/gen-avatars.mjs` (no flags) still behaves exactly as before — writes `pool.json`, prints the existing console output — since the entry-point guard only fires when the file is imported.
- `import('./tools/gen-avatars.mjs')` from the test file produces no side effects (no `mkdirSync`, no console output, no `codex` spawn) before any test runs.
- `ROADMAP.md` Phase 1 section mentions `--json` and accurately describes its behavior (stdout, not `pool.json`).

## Plan

### Approach
Extract the pure row-building step already inside `writeManifest()` into a standalone, exported `buildManifest()` function, and guard the script's top-level side effects (mkdir, generation loop, `process.exit`) behind an entry-point check so the module can be `import`ed for testing without running the generator. Add a `--json` flag that reuses `buildManifest()` to print the manifest to stdout instead of calling `writeFileSync`, and document the flag alongside the existing `tools/gen-avatars.mjs` description in ROADMAP Phase 1.

### Files
- `tools/gen-avatars.mjs` — add `--json` flag handling; extract `buildManifest(planned, isDone)` as an exported pure function; wrap the effectful "main" block (mkdir, codex generation loop, file writes, `process.exit`) in an `if (import.meta.url === ...)` guard so importing the module for tests doesn't execute it.
- `tools/gen-avatars.test.mjs` — new unit test for `buildManifest()`, covering row shaping (slug/label/file/color/colorName), the `version`/`palette` fields, and filtering out subjects whose PNG doesn't exist. Uses Node's built-in `node:test` + `node:assert`, since `tools/` has no existing test runner/dependency and isn't in the root `workspaces` array (only `server`/`web` are).
- `ROADMAP.md` — add one sentence documenting `--json` in the Phase 1 section (~line 185), next to the existing description of how `tools/gen-avatars.mjs` is run and what it commits.

### Steps
1. `tools/gen-avatars.mjs`: pull the row-mapping logic (lines 132–140) out of `writeManifest()` into `export function buildManifest(planned, isDone)`, returning `{ version: 1, avatars: rows, palette }`; `isDone(p)` replaces the inline `existsSync(join(OUT, ...))` check so the function takes no filesystem dependency directly.
2. `tools/gen-avatars.mjs`: add `const JSON_MODE = process.argv.includes('--json');` near the other `arg()`-derived flags; in `writeManifest()`, when `JSON_MODE` is true, `console.log(JSON.stringify(manifest, null, 2))` and return before the `writeFileSync`/log-line, instead of writing `pool.json`.
3. `tools/gen-avatars.mjs`: wrap the top-level generation block (from `mkdirSync(OUT, ...)` through the final `writeManifest()` call and any `process.exit(0)`) in a `if (import.meta.url === \`file://${process.argv[1]}\`)` guard so `import`-ing the file for a test only defines functions/constants.
4. `tools/gen-avatars.test.mjs`: write tests that `import { buildManifest } from './gen-avatars.mjs'`, pass a fixed `planned` array and a stub `isDone`, and assert the returned shape/filtering.
5. `ROADMAP.md`: add a sentence after the `tools/gen-avatars.mjs` description (~line 185) noting `--json` prints the manifest to stdout instead of writing `pool.json`.

### Risks
- The refactor (step 1 & 3) touches the script's control flow beyond a pure flag addition; if the entry-point guard is done carelessly it could break the documented CLI usage in the file's own header comment (`node tools/gen-avatars.mjs [--batch 4] ...`) — needs a manual dry-run, not just the unit test.
- No test runner is currently wired for `tools/` (root `package.json` `test` only covers the `server`/`web` workspaces); using bare `node:test` avoids new dependencies but means this test won't run under `npm test` unless that's also wired in — worth confirming with the user whether that's expected or out of scope.
- `writeManifest()` currently also logs `Manifest: N avatars -> path`; in `--json` mode this log must be suppressed or redirected to stderr so stdout stays valid JSON — easy to miss.
